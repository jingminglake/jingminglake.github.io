## 蓝图卡片

### 卡片：可变滑动窗口（核心蓝图）

**根本前提**：单调性 — 扩大窗口合法性只变差，缩小窗口合法性只变好。新题第一步先验证这个，不满足就不能用。

**三个核心问题**：
1. **窗口内维护什么？** 由"合法"的定义决定（计数器 / hash map / 单调队列）
2. **right 进攻** — 走到位置 i 时，left 之前所有位置与 i 的组合已全部处理，不遗漏
3. **left 防守** — 触发时机和目标由求最大还是求最小决定（见下方对比）

**求最大 vs 求最小 — left 的触发时机正好相反**：

| | 求最大窗口（如 1004） | 求最小窗口（如 LC 76） |
|--|---------------------|----------------------|
| left 移动时机 | 窗口**不合法**时 | 窗口**合法**时 |
| left 停止条件 | 停到刚好合法 | 停到刚好不合法 |
| left 的目标 | 找第一个合法位置 | 找最后一个合法位置（沿途记录答案） |

**复杂度**：摊还分析 — 单次 while 可能多步，但 left/right 全程只增不减，总计 O(2N)。

### 卡片：kSum 家族（核心蓝图）

**根本前提**：排序。有序后 left 右移变大、right 左移变小，每步能排除一整行/列，而非一个格子。

**三个核心问题**：
1. **是加还是减？** 加 → 对向（一头一尾）；减 → 同向（都从左出发）。无序且只求两数 → 直接哈希
2. **单边还是双边？** 单边（`<`/`>`）→ 直接双指针；双边或"恰好"→ 拆成两个单边相减
3. **要内容还是要数量？** 要内容 → 去重；要数量 → 不去重，但要想清一次加多少、等号归哪支

外层固定哪一个：多数题固定最小（内层从 `i+1` 起，避免重复用同一下标）；由"最大边"定义合法性的题（611）固定最大。

### 卡片：为什么加是对向、减是同向

画两张上三角表（格子 = 两元素的和 / 差）：

| | 表的单调性 | 起点 | 两个动作 | 形状 |
|--|-----------|------|---------|------|
| 加 | 右↑ 下↑ | 右上角 | `j--` 变小 / `i++` 变大 → 效果**相反** | 相向而行 |
| 减 | 右↑ 下↓ | 左上角 | `j++` 变大 / `i++` 变小 → 都**往前** | 同向前进 |

要点：你需要一个既能调大又能调小的起点，几何形状是这个需求逼出来的。

两者省的东西不同：对向靠**有序性**排除整行整列；同向靠**单调性**避免回退（摊还 O(2N)，和滑动窗口同一论证）。

### 卡片：259 的两条排除逻辑（地基题）

- **满足时**：`nums[right]` 是右边最大的，它都行 → `left` 配 `[left+1, right]` 任何一个都合法，`res += right - left`，这一行数完退休 → `left++`
- **不满足时**：`nums[left]` 是左边最小的，它都超标 → `right` 整列作废 → `right--`

注意 `res += right - left` **只消掉一行，不是整张表**。

每步只有一个动作，由当前格子的值唯一决定，**不存在分叉**。终止：每轮必移动一个指针且朝对方靠拢。

| 259 | `sum < target` | 不满足 | `right--` |
| 2563 `countLE` | `sum <= X` | 满足 | 记账后 `left++` |

### 卡片：双指针不是搜索（心智模型）

**不存在"逼近"**——和值不朝 target 收敛，路径形状由数据决定、事先看不出。刚性的只有：`left` 只增、`right` 只减，永不回头。

**正确性不来自路径**，来自不变量：*所有还没数过的合法对，一定落在 `[left, right]` 里*。每次移动前先证明"扔掉的这行/列不含未数过的合法对"，路径是副产品。

和二分划界：

| | 有无逼近 | 因为 |
|--|---------|------|
| 二分 | 有 | 目标是**命中一个位置** |
| 双指针 | 无 | 目标是**扫完整张表** |

不确定动哪个时，别问"该往哪走"，问"**这一行数完了吗**"。

**降维**：kSum = 前 k-2 层循环固定 + 最后 2 层双指针，O(N^(k-1))。内层从 `i+1` 开始是为了避免重复使用同一下标。

### 卡片：15 的三处去重

1. 外层：`i > 0 && nums[i] == nums[i-1]` → continue
2. 内层：找到解后 left 右跳、right 左跳，越过所有相同值
3. **跳完各再走一步并继续扫描** ← 本次讲解中未想起，是最易漏的一处

为什么要继续扫：同一个 i 下内层可能有多个不同 pair 都成立（如 i=-3，`[-1,1,2,4]` 中 `-1+4` 和 `1+2` 都是 3）。

### 卡片：并查集（Union Find）

**不可替代的信号**：**动态连通性** —— 边一条一条来、只增不减，每来一条要立刻回答"这两点连上了吗"。边若一开始就给全，DFS/BFS 也能做。

**模板三件套**：
1. `parent[i] = i`（必须初始化为自己，因为 find 的终止条件是 `parent[x] == x`）
2. `find`：`return parent[x] = find(parent[x]);` —— 回溯时顺手改挂（路径压缩）
3. `unite`：两根相同就 return；否则**小的挂大的**（按大小合并），`size` 累加，`count--`

**四档复杂度**（find 与 unite 永远相同，因为 unite 内含两次 find）：

| 优化 | find 摊还 |
|---|---|
| 无 | O(N) |
| 只按秩/按大小 | O(logN) |
| 只路径压缩 | O(logN) |
| 两者都做 | O(α(N)) |

α 是阿克曼函数的反函数，现实中 α(N) ≤ 5，但**写分析时不能写成 O(1)**。

**易错**：`union` 是 C++ 关键字，函数名要用 `unite`／`merge`。

### 卡片：并查集不能删边 → 时间倒流

**为什么做不到**：`parent` 只记录"我挂在谁身上"，不记录"我为什么挂上去"。合并有损不可逆，路径压缩更把树拍扁，无法还原。集合只能合、不能拆。

**反过来的通法**：

> 题目在"删边／删点／拆分" → **把时间倒过来**，变成"加边／加点／合并"。

代表题：803 Bricks Falling When Hit（倒序把打掉的砖加回去）、离线删边连通性查询。

**注意**：能做的事别误记成不能做 —— "列出某连通分量的所有成员"**是支持的**，遍历 parent 数组按根分组即可，只是 O(N) 而非 O(1)。

### 卡片：11 —— 单调性可以来自公式，不一定来自数据

**与 kSum 的分界**：kSum 靠排序让数据单调；11 **不排序**，单调性由 `min()` 这个公式本身提供。

**两根支柱（缺一不可）**：
1. **min 制造天花板** —— 矮的那根高度封顶（`min(3,·) ≤ 3`），已到顶；高的那根被拖累着，还有余地。
2. **从两端起步** —— 宽度只减不增，保证「当前这一对是各自够得着的最远伙伴」，退休论证才有前提。

合起来：**矮的那根正在最宽处且已封顶 → 巅峰就是现在 → 扔掉。**

**用户自己的说法（2026-09-13，最贴切）**：「以矮的为边的另一侧已经**极限**了；等高的时候两侧都极限了，因此移动哪一根都可以。」

**两边相等**：两侧同时到极限，移 l／移 r／一起移 `{l++; r--;}` 都对。
对比 kSum：11 的等号**自由**（只决定先扔谁），2563／259 的等号**必须定死**（决定这批算不算数）。

**对账（不漏解的真正含义）**：n=9 共 36 对，只算 8 对；扔一根柱子就连坐排除含它的所有未算候选，`8 + 28 = 36`。
**排除是结构性的** —— 排除时根本不看那批候选的值，否则又退回 O(N^2)。

**反证**：改成 `max(h[l],h[r])×(r-l)`，双指针**彻底崩塌**（两端谁都扔不掉）。
反例：`[1,100,1,1,2]` 移高的、`[2,100,1,1,1]` 移矮的，答案都是 300，两种规则都只给出 100。

**易错**：这**不是贪心**。贪心每步选元素纳入解；这里是删候选，答案由 `res = max(...)` 全量记录。
「每步都赚」是贪心的要求，「**不漏解**」才是排除法的要求。

### 卡片：路径不可追踪，正确性只能靠不变量

**卡点原话**（2026-09-13）：「每次移动方向根据两边高度动态变化，解空间不好想……这个点之前是什么，根本搞不清。」

**答**：搞不清是对的。路径由数据决定，改一个数就全变，**不携带信息，也不该追踪**。

**循环不变量**（任何路径下都成立）：
> 被扔出 `[l, r]` 之外的每根柱子，其参与的所有组合面积都 ≤ `res`。
> 等价：**最优解若还没被算到，它的两端一定都还在 `[l, r]` 内。**

终止时 `l == r`，区间塞不下任何一对 → 最优解必已算过。**证明全程不提路径。**

**为什么二分好懂、双指针难懂**：二分路径可预测（永远砍中点），人脑能跟着走；双指针跟不了。
少的不是理解，是**一种本来就不该依赖的理解方式**。

**收口**：不问「哪个点将来是答案」，只问「**眼前这两根，哪根没潜力了**」。答案不是被找到的，是被剩下的。

### 卡片：621 —— 构造 + 计数（不是贪心）

**先想清最优解长什么样，再把长度数出来，不模拟。**

**按 `n+1` 切行**：同任务两次至少差 `n+1` → **一行里同种任务最多出现一次** → 出现 `c` 次就占 `c` 个不同的行。

- `maxN`：最高频次（不是种类数，与题目 `n` 无关；代码里叫 `maxCount`）
- `countMax`：达到 `maxN` 的任务**种类数**

```
答案 = max((maxN-1) * (n+1) + countMax, tasks.size())
```

**末行为何恰好是 countMax**：`count < maxN` 的任务最多 `maxN-1` 个副本，前 `maxN-1` 行一定塞得下，够不着末行；
`count == maxN` 的占满全部 maxN 行，必然在末行各留一个。末行不用补满（后面没任务了）。

### 卡片：闭式公式题的两个自检

**动机**：621 的 `max(..., tasks.size())` 不是补丁，是推导必然要求的。怎么**想到**它 —— 三个入口：

1. **平凡下界撞公式**（最实用）：总时间必然 ≥ 任务总数。公式跌破下界 → 公式错。不需要理解溢出机制。
2. **参数推极端**（最快暴露）：`n=0` 时答案显然 = `tasks.size()`。代 `["A","A","B"]` → 公式给 2，真实 3，当场崩。
3. **追问隐含前提**（最本质）："低频任务前 `maxN-1` 行塞得下"默认了一行坐得下所有种类。种类 > `n+1` 就溢出。
   直观问法：**"idle 一定存在吗？"** 任务种类一多，坑被填满，零 idle → 答案就是任务总数。

**通法**：凡是推出闭式公式的题，交卷前固定做两件事 ——
（1）找回推导时说过"反正够／反正放得下"的那一步；（2）拿平凡上下界撞一下。

> **闭式公式是"跳过了模拟"换来的，跳过的那些步骤里就藏着边界。**

### 卡片：覆盖类滑动窗口的两种计数器

同一道 76，合法性可以压成两种整数，都是 O(1) 判断：

| | `missing`（数**个**） | `formed`（数**种**） |

| `t="AABC"` 时目标 | 4 → 0 | 0 → 3 |

### 卡片：297 序列化 —— # 的作用是标出子树边界

**唯一性从哪来**：单独的前／中／后序都无法唯一确定树（所以 105 要给两个）。
但**补上 `#` 之后，前序一个就够**——因为**前序的第一个元素永远是根**，读到它就能切出「接下来是左子树、然后右子树」，每棵子树读到哪结束由 `#` 显式告知。

中序不行：根埋在中间，不知道在哪切。后序可行（倒着读）。

> **`#` 的本质是把「子树在哪里结束」这个信息显式写进序列。**

**前序递归两大坑**：
1. 反序列化必须**共享同一个读取位置**（`istringstream&` 引用传递）；各层各持一份拷贝就全错。
2. `node->left = build(in);` 与 `node->right = build(in);` 必须是**两条独立语句** —— 写成一个表达式，C++ 求值顺序未定义，左右可能读反。

**前序 vs 层序**：代码 12 行 vs 25 行；输出长度都是 2N+1；
层序无递归（N=10^5 时前序会爆栈，但本题 N ≤ 10^4 够不着），且输出与 LeetCode 显示格式一致、好核对。

**易误判**：「层序是为了防爆栈」——理由真实但次要，且**避免递归不唯一指向 BFS**（前序可用显式栈改迭代）。
**结论**：面试默认前序递归。

### 卡片：42 接雨水 —— 按列算，核心是一个公式

```
water[i] = min(leftMax[i], rightMax[i]) - height[i]
```

`leftMax[i]` = `height[0..i]` 最大值，`rightMax[i]` = `height[i..n-1]` 最大值，**都含 i 自己**。

- **为何是 min**：木桶原理，水面由较矮那道墙决定。
- **为何非负**：两个 max 都包含 `height[i]` → `min >= height[i]`。**所以代码不需要判断"存不存得住水"**，直接减，存不住时恰好是 0。

全题化约为：**怎么快速拿到每个 i 的 leftMax / rightMax？**
暴力 O(N²) → 两遍预处理 O(N) 时间 O(N) 空间 → 对向双指针 O(N) 时间 **O(1) 空间**。

**双指针为何算矮的那根**：`LM` 已是 left 的**真实** leftMax；而 left 的真实 rightMax `>= height[right] > height[left]`，
所以 `min` 必落在 LM 这边，水量当场定死。高的那根内侧还没看，`min` 取哪边未定，算不出来。

### 卡片：11 vs 42 —— 同一个动作，保证的东西不同

两题都是对向双指针、都「移动矮的那根」、相等时都可移任意一侧。**但能否批量跳过不同：**

| | 11 | 42 |
|--|---|---|
| 移矮的保证了什么 | 它**已到顶**，最优搭档已算过 | 它**外侧信息已完整**，这一格水量可定死 |
| 答案由什么构成 | **一对** `(l,r)` 的面积 | **每一格**的水，逐格累加 |

**反例 `[5,1,5]`**：一起移 → `left==right==1`，循环直接结束，中间那根从未被访问，4 格水丢失，答案算成 0。

> **11 在「排除候选」，跳过不影响；42 在「逐格累加」，跳过就是漏项。**

### 卡片：295 双堆 —— 三步法，不判断新元素该进哪边

**两条不变量**：① `size(small) == size(large)` 或多 1；② `small.top() <= large.top()`。

**addNum 固定三步（顺序不能换）**：
1. 无脑塞 `small`
2. `small` 堆顶让给 `large` —— **管性质②**（左边最大的已被扔到右边）
3. `large` 若反超，堆顶还回 `small` —— **只管性质①**（数量）

先调数量再调值就错了。这套写法把所有分支都省掉，不需要比较新元素该进哪个堆。

**两个坑**：`/ 2.0` 不能写 `/ 2`（int 截断）；C++ 最小堆直接用 `greater<int>`，
别用"push 负数"老技巧（`INT_MIN` 取负溢出）。

### 卡片：480 滑动窗口中位数 —— 三个容器坑

**为何双堆失效**：堆只能看／弹堆顶，**不支持删除任意元素**；窗口右移要踢的那个数可能埋在堆中间。
→ 换成有序 + 可任意删除的结构：C++ `multiset`，Java `TreeSet`。

**坑一（C++）**：`multiset::erase(value)` 删**所有**相同值 → 必须 `erase(find(x))`。

**坑二（Java）**：`TreeSet` 不收重复元素 → 存 **index** 而非值。
**但光存 index 不够** —— 比较器必须用 index 做 tie-break：
```java
(a, b) -> nums[a] != nums[b] ? Integer.compare(nums[a], nums[b])
                             : Integer.compare(a, b);   // ← 解药
```
否则同值不同下标仍被判相等，照样被吞。附带好处：删除时手上有下标，`remove(i)` 精确删除。

> 坑一与坑二正好成对：**同是"容器怎么处理重复值"，C++ 删太多，Java 存不进**。

**坑三**：求中位数 **int 溢出** —— 本题范围 `[-2^31, 2^31-1]`，官方用例有 `[INT_MAX, INT_MAX]`。
必须 `((double)a + b) / 2`，不能 `(a + b) / 2.0`。295 遇不到，480 独有。

**单 multiset 写法**：`next(it, n)` 是 O(n)（双向迭代器），每次从 `begin()` 走会退化成 O(N·K)。
正解是**保存 `mid` 迭代器、每次只挪 ±1 步**；删到 `mid` 本身时要**先挪开再删**，否则迭代器失效。

### 卡片：224 计算器 —— 三变量 + 括号即一个数

**三变量**：`res`（本层已算出的）、`sign`（未参与计算的正负号）、`number`（未读完／未参与计算的数）。

**res 的触发点**：`+`、`-`、`)`、字符串结尾。遇到数字只更新 `number`；**左括号不触发**（它压栈）。
为何是这几个：res 只能在「一个数已完整读完、且符号已确定」时更新；数字可能多位，读到非数字才知道读完。

**开头无需特判**：首字符若是 `-`，触发的那次更新 `res += sign*0` 是空操作。

**跨层的关键认识**：**每一层的结果以 `number` 的形式回到上一层——一对括号在上层眼里就是一个数。**
于是跨层逻辑统一进同一套三变量模型，不需要额外规则；也解释了 `)` 为何在触发名单里——**带回一个数，有数就要结算**。

- **进层（`(`）**：压 `res` 和 `sign` 两个（`sign` 必压，因为 `1 - (2+3)` 的减号作用于整个括号）；
  `number` 此刻**必然为 0**（左括号前不可能紧跟数字），不用保存。然后 `res=0, sign=1`。
- **出层（`)`）**：本层结算 → 弹栈**恢复** `res`、`sign` → 把本层结果**赋给** `number` → 立即触发 res 更新。
  注意：恢复两个、赋值一个，`number` 不是恢复来的。

**立即折叠只在 224 成立**（只有加减）。772 带乘除时，括号结果必须先停在 `number` 里，
等下一个运算符才知道该加减还是该乘除。

### 卡片：dp 状态定义的方向 —— 以 i 结尾 vs 以 i 起头

**默认套路**是「以 i 结尾／前 i 个」。但有一类题必须反过来。

> **判据：当「当前决策是否合法／有多好」取决于后面还没走的部分时，必须从后往前定义。**

| | 以 i 结尾 | 以 i 起头 |
|--|---|---|
| 扫描方向 | 正序 | 逆序 |
| 答案位置 | `dp[n-1]` / `dp[n]` | **`dp[0]`** |

**174 Dungeon Game 是最纯粹的例证**：血量 ≥ 1 这个约束是**未来的**——能不能活取决于后面还要掉多少血，
正向推时这个信息根本不存在。所以状态必须是「从 (i,j) 出发到终点所需的最少初始血量」。

**139 Word Break 两个方向都成立**，是最好的对照样本。
区间 dp（5/516）是「两端都定死」的第三类；树形 dp 的「从 i 起头」= 「以 i 为根的子树」。

### 卡片：1235 —— 等权则贪心，带权则 dp

**与 435 的分水岭只有一个字：权重。**
435 每个区间等权 → 「按结束时间排序、能选就选」的贪心成立；
1235 带 profit → 贪心崩。反例：`(0,10,100)` vs `(0,1,1)(1,2,1)(2,3,1)`，贪心得 3，正解 100。

**推荐解法：按结束时间排序 + dp + 二分**，O(NlogN)。
`dp[i]` = 只考虑前 i 个工作的最大利润（属「以 i 结尾」）。
转移：`dp[i] = max(dp[i-1], dp[k] + profit)`，`k` = 结束时间 ≤ 当前开始时间的工作数，用 **upper_bound** 求。

**三个要点**：
1. **按结束时间排序**，因为查询问的是结束时间；按开始时间排则要改成「从 i 起头」+ 逆序（呼应上一张卡片）
2. `k` 不会算进当前工作 —— start < end 且 ends 升序，upper_bound 必落在当前之前
3. `dp[k]` 可直接用 —— **dp 单调不减**

**变体**：map 维护单调阶梯（end → 最大利润），只在变优时写入，本质是把 dp 压成只存拐点。

**综合性**：这题接起了区间排序（57/435）+ 二分 upper_bound（总结三）+ 带权 dp。

### 卡片：BST 上的四个 bound —— 一个模板

> **从 root 一路下行，走「错」方向的那一步把当前结点记为候选；走到空为止，最后记下的候选就是答案。**

「走错方向」= 当前结点已满足条件，但可能还有更贴近 x 的，所以先存再找。

| 要找 | 名称 | 向右走的条件 | 记录时机 |
|---|---|---|---|
| 最小的 `> x` | upper_bound／后继（285） | `cur <= x` | 向左走时 |
| 最小的 `>= x` | lower_bound／ceiling | `cur < x` | 向左走时 |
| 最大的 `<= x` | floor | `cur <= x` | **向右走时** |
| 最大的 `< x` | 严格前驱 | `cur < x` | **向右走时** |

**两组对照**：
1. 前两行只差一个等号 —— 就是数组二分里那个「**等号归哪一边**」（见总结三）：归右跳过相等者（严格大于），归左留下它（大于等于）。
2. 前两行 vs 后两行**方向相反** —— 求「> x 的最小」在向左时记录（左边更小更贴近），求「< x 的最大」在向右时记录。

O(h)，不需要父指针，不需要递归。**记住那一句就能现推四个，不必分别背。**

### 卡片：单调栈 —— 栈的方向与所求相反

**解决的问题**：为每个元素找左右两侧**最近的、第一个满足某大小关系**的元素。

| 要找 | 栈里维持 | 弹栈时机 |
|---|---|---|
| 最近的**更小** | **递增**栈 | 当前 < 栈顶 |
| 最近的**更大** | **递减**栈 | 当前 > 栈顶 |

> **记忆法：破坏单调性的那个元素，正是被弹出者要找的答案。**
> 想找「更小」，就得让「更小」成为破坏者，栈自然递增。

**弹栈那一刻两个边界一起到手**：当前元素 = 被弹出者的右边界；弹出后的新栈顶 = 它的左边界。这才是它省时间的地方。

**84 的两个坑**：
1. **收尾** —— 扫完栈里还剩一批（右边界是 n）。最省事是**末尾追加高度 0 的哨兵**，循环自然清空栈；头部也可加 0 哨兵省掉「栈空时左边界 -1」的判断。同类边界见 224／227 的"扫到末尾要收尾"。
2. **等号为何安全** —— 相等时提前结算宽度偏窄，但**那根柱子应得的完整宽度会由后面等高的那根算出来**，所以不漏。推论：相等时压栈或弹栈**都能过**（"等号归属自由"，对照 kSum 计数题必须定死）。

**家族**：84（递增栈）→ 85（逐行跑 84）→ 239（递减双端队列，多一条下标过期）→ 42（递减栈**横着一层层积水**，与总结二的双指针**竖着按列算**互为视角）。

### 卡片：253 排序+堆 —— 五个环节，缺一个就觉得别扭

**（0）语义先建立起来**（用户自述第一眼没看见的就是这条）：
> 堆里每个元素 = **一间正在被占用的房间**，值是它何时空出来。
> **`pq.size()` 不是「剩下几个会」，是「开了几间房」。**

**（1）为何只查堆顶**：堆顶是最早结束的那间；它都没空，别的结束更晚，必然也占着。

**（2）为何每次最多只弹一个**：只安排一个会，只需一间房。残留的「已结束未弹出」条目不会多算
——那些房间确实分配过；且 **start 单调不减**，它们后面仍可被弹出复用。

**（3）为何终值即答案**：每轮最多弹 1、必定压 1 → 堆大小**只增不减** → 终值 = 最大值，
不必维护 `res = max(res, pq.size())`。

**（4）桥（把「分配房间」和「最大重叠数」对上）**：
```
start < 堆顶(最小 end)
  ⟺ start < 堆里所有 end
  ⟺ 已开的每间房此刻都在用
  ⟺ 此刻同时进行数 = 已开房间数 + 1   ← 创新高
```
> **堆大小的增长史 = 最大重叠数的刷新史。**堆解法是「一边分配、一边把最大重叠数数出来」。

**（5）`>=` 不能写成 `>`**：`[[1,5],[5,10]]` 共用一间，答案 1。

**排序的作用是双重的**：不只是给出时间顺序，「start 单调不减」还是第（2）点成立的**前提**。

### 方法论卡片：先建「当前状态」模型，再接受「累计资源」这种技巧（用户 2026-09-19 自述）

用户原话：**「我的思路对于『当前在开的会』比较敏感，很难想到是『开的房间数量』。」**

**这个直觉是对的，不是短板。**题目的答案定义就是「最大同时重叠数」——
「当前在开的会」**直接**对应这个定义；「已开房间数」是**间接**的，恰好等于前者但需要额外论证。

| | 语义 | 对应 |
|--|------|------|
| **当前状态**模型 | 堆 = 当前在开的会，大小 = 当前重叠数，答案 = **峰值** | 题目定义本身 |
| **累计资源**模型 | 堆 = 已开房间，大小只增不减，答案 = **终值** | 一个省变量的技巧 |

> **「累计资源」写法的本质是：把「记录历史最大值」偷换成「让堆大小自己只增不减」。**
> 省一个变量，代价是语义从「当前重叠数」变成「已开房间数」。

**如何应用**：讲这类题时**先给当前状态模型**（语义透明、与定义直接对应），
再把累计资源写法作为「更短的变体」介绍，并明确点出它省掉了什么、代价是什么。
不要反过来——反过来会让人觉得「缺了一个东西」。

**同族**：1094 Car Pooling（峰值乘客数）、1109 Corporate Flight Bookings、
扫描线全家族。凡是「最少需要多少资源」的题，多半等价于「峰值并发数」，
**想峰值比想资源池更直接**。

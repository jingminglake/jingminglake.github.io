## 蓝图卡片

### 卡片：可变滑动窗口（核心蓝图）

**根本前提**：单调性 — 扩大窗口合法性只变差，缩小窗口合法性只变好。新题第一步先验证这个，不满足就不能用。

**三个核心问题**：
1. **窗口内维护什么？** 由"合法"的定义决定（计数器 / hash map / 单调队列）
2. **right 进攻** — 走到位置 i 时，left 之前所有位置与 i 的组合已全部处理，不遗漏
3. **left 防守** — 触发时机和目标由求最大还是求最小决定（见下方对比）

**求最大 vs 求最小 — left 的触发时机正好相反**：

| | 求最大窗口（如 1004） | 求最小窗口（如 LC 76） |
|--|---------------------|----------------------|
| left 移动时机 | 窗口**不合法**时 | 窗口**合法**时 |
| left 停止条件 | 停到刚好合法 | 停到刚好不合法 |
| left 的目标 | 找第一个合法位置 | 找最后一个合法位置（沿途记录答案） |

**复杂度**：摊还分析 — 单次 while 可能多步，但 left/right 全程只增不减，总计 O(2N)。

### 卡片：1004 — 至多 k 个 0

- 维护：`zeros`（窗口内 0 的个数）
- 不合法：`zeros > k`
- 收缩：while，每次 right 最多引入 1 个 0，但消除它可能要扫过多个 1

### 卡片：Leetcode 3 — 无重复字符

- 维护：hash map（字符 → 最后出现下标）
- 不合法：新字符的 `last_seen[c] >= left`（在窗口内才算重复）
- 收缩：**不需要 while**，`left = last_seen[c] + 1` 一跳到位
- 为什么一跳到位：每次 right 只引入一个字符，窗口内最多一个旧副本

| | 1004 | LC 3 |
|--|------|------|
| 每次 right 引入几个违规 | 最多 1 个 0 | 最多 1 个重复 |
| 消除违规需要几步 | 不定（要扫过 1）→ while | 恰好 1 步（位置已知）→ if |

### 卡片：kSum 家族（核心蓝图）

**根本前提**：排序。有序后 left 右移变大、right 左移变小，每步能排除一整行/列，而非一个格子。

**三个核心问题**：
1. **是加还是减？** 加 → 对向（一头一尾）；减 → 同向（都从左出发）。无序且只求两数 → 直接哈希
2. **单边还是双边？** 单边（`<`/`>`）→ 直接双指针；双边或"恰好"→ 拆成两个单边相减
3. **要内容还是要数量？** 要内容 → 去重；要数量 → 不去重，但要想清一次加多少、等号归哪支

外层固定哪一个：多数题固定最小（内层从 `i+1` 起，避免重复用同一下标）；由"最大边"定义合法性的题（611）固定最大。

### 卡片：为什么加是对向、减是同向

画两张上三角表（格子 = 两元素的和 / 差）：

| | 表的单调性 | 起点 | 两个动作 | 形状 |
|--|-----------|------|---------|------|
| 加 | 右↑ 下↑ | 右上角 | `j--` 变小 / `i++` 变大 → 效果**相反** | 相向而行 |
| 减 | 右↑ 下↓ | 左上角 | `j++` 变大 / `i++` 变小 → 都**往前** | 同向前进 |

要点：你需要一个既能调大又能调小的起点，几何形状是这个需求逼出来的。

两者省的东西不同：对向靠**有序性**排除整行整列；同向靠**单调性**避免回退（摊还 O(2N)，和滑动窗口同一论证）。

### 卡片：259 的两条排除逻辑（地基题）

- **满足时**：`nums[right]` 是右边最大的，它都行 → `left` 配 `[left+1, right]` 任何一个都合法，`res += right - left`，这一行数完退休 → `left++`
- **不满足时**：`nums[left]` 是左边最小的，它都超标 → `right` 整列作废 → `right--`

注意 `res += right - left` **只消掉一行，不是整张表**。

每步只有一个动作，由当前格子的值唯一决定，**不存在分叉**。终止：每轮必移动一个指针且朝对方靠拢。

### 卡片：2563 前缀之差

`lower ≤ sum ≤ upper` = `countLE(upper) − countLE(lower-1)`，每一半退回成 259。

为什么不能直接做：双边约束下合法段**悬在中间**，一行里可能一部分太小一部分太大，没法用一个 `right-left` 批量数。单边才有"合法段贴着一端"的性质。

同族套路：992「恰好k = 至多k − 至多k-1」。见到"恰好""区间内"先想拆。

### 卡片：等号归哪一边（易错）

推导两步，中间不能跳：
1. 等号归哪一支？← 由题目符号决定（`≤` 还是 `<`）
2. 那一支的固定动作？← 满足就 `left++`，不满足就 `right--`

| 题 | 条件 | 等号 | 动作 |
|---|------|------|------|
| 259 | `sum < target` | 不满足 | `right--` |
| 2563 `countLE` | `sum <= X` | 满足 | 记账后 `left++` |
| 611 | `a+b > c` | 不满足 | — |

259 和 countLE 的等号**移动方向相反**，所以「等号往大走」不是规律，别背。

### 卡片：双指针不是搜索（心智模型）

**不存在"逼近"**——和值不朝 target 收敛，路径形状由数据决定、事先看不出。刚性的只有：`left` 只增、`right` 只减，永不回头。

**正确性不来自路径**，来自不变量：*所有还没数过的合法对，一定落在 `[left, right]` 里*。每次移动前先证明"扔掉的这行/列不含未数过的合法对"，路径是副产品。

和二分划界：

| | 有无逼近 | 因为 |
|--|---------|------|
| 二分 | 有 | 目标是**命中一个位置** |
| 双指针 | 无 | 目标是**扫完整张表** |

不确定动哪个时，别问"该往哪走"，问"**这一行数完了吗**"。

**降维**：kSum = 前 k-2 层循环固定 + 最后 2 层双指针，O(N^(k-1))。内层从 `i+1` 开始是为了避免重复使用同一下标。

### 卡片：15 的三处去重

1. 外层：`i > 0 && nums[i] == nums[i-1]` → continue
2. 内层：找到解后 left 右跳、right 左跳，越过所有相同值
3. **跳完各再走一步并继续扫描** ← 本次讲解中未想起，是最易漏的一处

为什么要继续扫：同一个 i 下内层可能有多个不同 pair 都成立（如 i=-3，`[-1,1,2,4]` 中 `-1+4` 和 `1+2` 都是 3）。

### 卡片对比：去重 vs 计数

| | 15（要内容） | 923（要数量） |
|--|-------------|--------------|
| 遇到一段重复值 | 跳过 | 用组合数数清楚 |
| 原因 | 值相同的三元组算重复 | 下标不同就算不同答案 |
| 操作 | while 跳过 + 各走一步 | `c1*c2` 或 `C(m,2)` |

### 卡片对比：16 vs 259

扫描过程完全一样（left/right 交替往中间收，O(N) 步）。区别只在每步做什么：
- 16：更新一个最优值
- 259：`res += right - left` 累加一整行，注意这只消掉一行不是整张表，仍要继续走

### 卡片：并查集（Union Find）

**不可替代的信号**：**动态连通性** —— 边一条一条来、只增不减，每来一条要立刻回答"这两点连上了吗"。边若一开始就给全，DFS/BFS 也能做。

**模板三件套**：
1. `parent[i] = i`（必须初始化为自己，因为 find 的终止条件是 `parent[x] == x`）
2. `find`：`return parent[x] = find(parent[x]);` —— 回溯时顺手改挂（路径压缩）
3. `unite`：两根相同就 return；否则**小的挂大的**（按大小合并），`size` 累加，`count--`

**四档复杂度**（find 与 unite 永远相同，因为 unite 内含两次 find）：

| 优化 | find 摊还 |
|---|---|
| 无 | O(N) |
| 只按秩/按大小 | O(logN) |
| 只路径压缩 | O(logN) |
| 两者都做 | O(α(N)) |

α 是阿克曼函数的反函数，现实中 α(N) ≤ 5，但**写分析时不能写成 O(1)**。

**易错**：`union` 是 C++ 关键字，函数名要用 `unite`／`merge`。

### 卡片：并查集不能删边 → 时间倒流

**为什么做不到**：`parent` 只记录"我挂在谁身上"，不记录"我为什么挂上去"。合并有损不可逆，路径压缩更把树拍扁，无法还原。集合只能合、不能拆。

**反过来的通法**：

> 题目在"删边／删点／拆分" → **把时间倒过来**，变成"加边／加点／合并"。

代表题：803 Bricks Falling When Hit（倒序把打掉的砖加回去）、离线删边连通性查询。

**注意**：能做的事别误记成不能做 —— "列出某连通分量的所有成员"**是支持的**，遍历 parent 数组按根分组即可，只是 O(N) 而非 O(1)。

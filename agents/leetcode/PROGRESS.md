## 蓝图卡片

### 卡片：可变滑动窗口（核心蓝图）

**根本前提**：单调性 — 扩大窗口合法性只变差，缩小窗口合法性只变好。新题第一步先验证这个，不满足就不能用。

**三个核心问题**：
1. **窗口内维护什么？** 由"合法"的定义决定（计数器 / hash map / 单调队列）
2. **right 进攻** — 走到位置 i 时，left 之前所有位置与 i 的组合已全部处理，不遗漏
3. **left 防守** — 触发时机和目标由求最大还是求最小决定（见下方对比）

**求最大 vs 求最小 — left 的触发时机正好相反**：

| | 求最大窗口（如 1004） | 求最小窗口（如 LC 76） |
|--|---------------------|----------------------|
| left 移动时机 | 窗口**不合法**时 | 窗口**合法**时 |
| left 停止条件 | 停到刚好合法 | 停到刚好不合法 |
| left 的目标 | 找第一个合法位置 | 找最后一个合法位置（沿途记录答案） |

**复杂度**：摊还分析 — 单次 while 可能多步，但 left/right 全程只增不减，总计 O(2N)。

### 卡片：1004 — 至多 k 个 0

- 维护：`zeros`（窗口内 0 的个数）
- 不合法：`zeros > k`
- 收缩：while，每次 right 最多引入 1 个 0，但消除它可能要扫过多个 1

### 卡片：Leetcode 3 — 无重复字符

- 维护：hash map（字符 → 最后出现下标）
- 不合法：新字符的 `last_seen[c] >= left`（在窗口内才算重复）
- 收缩：**不需要 while**，`left = last_seen[c] + 1` 一跳到位
- 为什么一跳到位：每次 right 只引入一个字符，窗口内最多一个旧副本

### 卡片对比：while vs 一跳到位

| | 1004 | LC 3 |

| 每次 right 引入几个违规 | 最多 1 个 0 | 最多 1 个重复 |
| 消除违规需要几步 | 不定（要扫过 1）→ while | 恰好 1 步（位置已知）→ if |

### 卡片：kSum 家族（核心蓝图）

**根本前提**：排序。有序后 left 右移变大、right 左移变小，每步能排除一整行/列，而非一个格子。

**三个核心问题**：
1. **是加还是减？** 加 → 对向（一头一尾）；减 → 同向（都从左出发）。无序且只求两数 → 直接哈希
2. **单边还是双边？** 单边（`<`/`>`）→ 直接双指针；双边或"恰好"→ 拆成两个单边相减
3. **要内容还是要数量？** 要内容 → 去重；要数量 → 不去重，但要想清一次加多少、等号归哪支

外层固定哪一个：多数题固定最小（内层从 `i+1` 起，避免重复用同一下标）；由"最大边"定义合法性的题（611）固定最大。

### 卡片：为什么加是对向、减是同向

画两张上三角表（格子 = 两元素的和 / 差）：

| | 表的单调性 | 起点 | 两个动作 | 形状 |
|--|-----------|------|---------|------|
| 加 | 右↑ 下↑ | 右上角 | `j--` 变小 / `i++` 变大 → 效果**相反** | 相向而行 |
| 减 | 右↑ 下↓ | 左上角 | `j++` 变大 / `i++` 变小 → 都**往前** | 同向前进 |

要点：你需要一个既能调大又能调小的起点，几何形状是这个需求逼出来的。

两者省的东西不同：对向靠**有序性**排除整行整列；同向靠**单调性**避免回退（摊还 O(2N)，和滑动窗口同一论证）。

### 卡片：259 的两条排除逻辑（地基题）

- **满足时**：`nums[right]` 是右边最大的，它都行 → `left` 配 `[left+1, right]` 任何一个都合法，`res += right - left`，这一行数完退休 → `left++`
- **不满足时**：`nums[left]` 是左边最小的，它都超标 → `right` 整列作废 → `right--`

注意 `res += right - left` **只消掉一行，不是整张表**。

每步只有一个动作，由当前格子的值唯一决定，**不存在分叉**。终止：每轮必移动一个指针且朝对方靠拢。

### 卡片：2563 前缀之差

`lower ≤ sum ≤ upper` = `countLE(upper) − countLE(lower-1)`，每一半退回成 259。

为什么不能直接做：双边约束下合法段**悬在中间**，一行里可能一部分太小一部分太大，没法用一个 `right-left` 批量数。单边才有"合法段贴着一端"的性质。

同族套路：992「恰好k = 至多k − 至多k-1」。见到"恰好""区间内"先想拆。

### 卡片：等号归哪一边（易错）

推导两步，中间不能跳：
1. 等号归哪一支？← 由题目符号决定（`≤` 还是 `<`）
2. 那一支的固定动作？← 满足就 `left++`，不满足就 `right--`

| 题 | 条件 | 等号 | 动作 |
|---|------|------|------|
| 259 | `sum < target` | 不满足 | `right--` |
| 2563 `countLE` | `sum <= X` | 满足 | 记账后 `left++` |
| 611 | `a+b > c` | 不满足 | — |

259 和 countLE 的等号**移动方向相反**，所以「等号往大走」不是规律，别背。

### 卡片：双指针不是搜索（心智模型）

**不存在"逼近"**——和值不朝 target 收敛，路径形状由数据决定、事先看不出。刚性的只有：`left` 只增、`right` 只减，永不回头。

**正确性不来自路径**，来自不变量：*所有还没数过的合法对，一定落在 `[left, right]` 里*。每次移动前先证明"扔掉的这行/列不含未数过的合法对"，路径是副产品。

和二分划界：

| | 有无逼近 | 因为 |
|--|---------|------|
| 二分 | 有 | 目标是**命中一个位置** |
| 双指针 | 无 | 目标是**扫完整张表** |

不确定动哪个时，别问"该往哪走"，问"**这一行数完了吗**"。

**降维**：kSum = 前 k-2 层循环固定 + 最后 2 层双指针，O(N^(k-1))。内层从 `i+1` 开始是为了避免重复使用同一下标。

### 卡片：15 的三处去重

1. 外层：`i > 0 && nums[i] == nums[i-1]` → continue
2. 内层：找到解后 left 右跳、right 左跳，越过所有相同值
3. **跳完各再走一步并继续扫描** ← 本次讲解中未想起，是最易漏的一处

为什么要继续扫：同一个 i 下内层可能有多个不同 pair 都成立（如 i=-3，`[-1,1,2,4]` 中 `-1+4` 和 `1+2` 都是 3）。

### 卡片对比：去重 vs 计数

| | 15（要内容） | 923（要数量） |
|--|-------------|--------------|
| 遇到一段重复值 | 跳过 | 用组合数数清楚 |
| 原因 | 值相同的三元组算重复 | 下标不同就算不同答案 |
| 操作 | while 跳过 + 各走一步 | `c1*c2` 或 `C(m,2)` |

### 卡片对比：16 vs 259

扫描过程完全一样（left/right 交替往中间收，O(N) 步）。区别只在每步做什么：
- 16：更新一个最优值
- 259：`res += right - left` 累加一整行，注意这只消掉一行不是整张表，仍要继续走

### 卡片：并查集（Union Find）

**不可替代的信号**：**动态连通性** —— 边一条一条来、只增不减，每来一条要立刻回答"这两点连上了吗"。边若一开始就给全，DFS/BFS 也能做。

**模板三件套**：
1. `parent[i] = i`（必须初始化为自己，因为 find 的终止条件是 `parent[x] == x`）
2. `find`：`return parent[x] = find(parent[x]);` —— 回溯时顺手改挂（路径压缩）
3. `unite`：两根相同就 return；否则**小的挂大的**（按大小合并），`size` 累加，`count--`

**四档复杂度**（find 与 unite 永远相同，因为 unite 内含两次 find）：

| 优化 | find 摊还 |
|---|---|
| 无 | O(N) |
| 只按秩/按大小 | O(logN) |
| 只路径压缩 | O(logN) |
| 两者都做 | O(α(N)) |

α 是阿克曼函数的反函数，现实中 α(N) ≤ 5，但**写分析时不能写成 O(1)**。

**易错**：`union` 是 C++ 关键字，函数名要用 `unite`／`merge`。

### 卡片：并查集不能删边 → 时间倒流

**为什么做不到**：`parent` 只记录"我挂在谁身上"，不记录"我为什么挂上去"。合并有损不可逆，路径压缩更把树拍扁，无法还原。集合只能合、不能拆。

**反过来的通法**：

> 题目在"删边／删点／拆分" → **把时间倒过来**，变成"加边／加点／合并"。

代表题：803 Bricks Falling When Hit（倒序把打掉的砖加回去）、离线删边连通性查询。

**注意**：能做的事别误记成不能做 —— "列出某连通分量的所有成员"**是支持的**，遍历 parent 数组按根分组即可，只是 O(N) 而非 O(1)。

### 卡片：11 —— 单调性可以来自公式，不一定来自数据

**与 kSum 的分界**：kSum 靠排序让数据单调；11 **不排序**，单调性由 `min()` 这个公式本身提供。

**两根支柱（缺一不可）**：
1. **min 制造天花板** —— 矮的那根高度封顶（`min(3,·) ≤ 3`），已到顶；高的那根被拖累着，还有余地。
2. **从两端起步** —— 宽度只减不增，保证「当前这一对是各自够得着的最远伙伴」，退休论证才有前提。

合起来：**矮的那根正在最宽处且已封顶 → 巅峰就是现在 → 扔掉。**

**用户自己的说法（2026-09-13，最贴切）**：「以矮的为边的另一侧已经**极限**了；等高的时候两侧都极限了，因此移动哪一根都可以。」

**两边相等**：两侧同时到极限，移 l／移 r／一起移 `{l++; r--;}` 都对。
对比 kSum：11 的等号**自由**（只决定先扔谁），2563／259 的等号**必须定死**（决定这批算不算数）。

**对账（不漏解的真正含义）**：n=9 共 36 对，只算 8 对；扔一根柱子就连坐排除含它的所有未算候选，`8 + 28 = 36`。
**排除是结构性的** —— 排除时根本不看那批候选的值，否则又退回 O(N^2)。

**反证**：改成 `max(h[l],h[r])×(r-l)`，双指针**彻底崩塌**（两端谁都扔不掉）。
反例：`[1,100,1,1,2]` 移高的、`[2,100,1,1,1]` 移矮的，答案都是 300，两种规则都只给出 100。

**易错**：这**不是贪心**。贪心每步选元素纳入解；这里是删候选，答案由 `res = max(...)` 全量记录。
「每步都赚」是贪心的要求，「**不漏解**」才是排除法的要求。

### 卡片：路径不可追踪，正确性只能靠不变量

**卡点原话**（2026-09-13）：「每次移动方向根据两边高度动态变化，解空间不好想……这个点之前是什么，根本搞不清。」

**答**：搞不清是对的。路径由数据决定，改一个数就全变，**不携带信息，也不该追踪**。

**循环不变量**（任何路径下都成立）：
> 被扔出 `[l, r]` 之外的每根柱子，其参与的所有组合面积都 ≤ `res`。
> 等价：**最优解若还没被算到，它的两端一定都还在 `[l, r]` 内。**

终止时 `l == r`，区间塞不下任何一对 → 最优解必已算过。**证明全程不提路径。**

**为什么二分好懂、双指针难懂**：二分路径可预测（永远砍中点），人脑能跟着走；双指针跟不了。
少的不是理解，是**一种本来就不该依赖的理解方式**。

**收口**：不问「哪个点将来是答案」，只问「**眼前这两根，哪根没潜力了**」。答案不是被找到的，是被剩下的。

### 卡片：621 —— 构造 + 计数（不是贪心）

**先想清最优解长什么样，再把长度数出来，不模拟。**

**按 `n+1` 切行**：同任务两次至少差 `n+1` → **一行里同种任务最多出现一次** → 出现 `c` 次就占 `c` 个不同的行。

- `maxN`：最高频次（不是种类数，与题目 `n` 无关；代码里叫 `maxCount`）
- `countMax`：达到 `maxN` 的任务**种类数**

```
答案 = max((maxN-1) * (n+1) + countMax, tasks.size())
```

**末行为何恰好是 countMax**：`count < maxN` 的任务最多 `maxN-1` 个副本，前 `maxN-1` 行一定塞得下，够不着末行；
`count == maxN` 的占满全部 maxN 行，必然在末行各留一个。末行不用补满（后面没任务了）。

### 卡片：闭式公式题的两个自检

**动机**：621 的 `max(..., tasks.size())` 不是补丁，是推导必然要求的。怎么**想到**它 —— 三个入口：

1. **平凡下界撞公式**（最实用）：总时间必然 ≥ 任务总数。公式跌破下界 → 公式错。不需要理解溢出机制。
2. **参数推极端**（最快暴露）：`n=0` 时答案显然 = `tasks.size()`。代 `["A","A","B"]` → 公式给 2，真实 3，当场崩。
3. **追问隐含前提**（最本质）："低频任务前 `maxN-1` 行塞得下"默认了一行坐得下所有种类。种类 > `n+1` 就溢出。
   直观问法：**"idle 一定存在吗？"** 任务种类一多，坑被填满，零 idle → 答案就是任务总数。

**通法**：凡是推出闭式公式的题，交卷前固定做两件事 ——
（1）找回推导时说过"反正够／反正放得下"的那一步；（2）拿平凡上下界撞一下。

> **闭式公式是"跳过了模拟"换来的，跳过的那些步骤里就藏着边界。**

### 卡片：覆盖类滑动窗口的两种计数器

同一道 76，合法性可以压成两种整数，都是 O(1) 判断：

| | `missing`（数**个**） | `formed`（数**种**） |
|--|---|---|
| `t="AABC"` 时目标 | 4 → 0 | 0 → 3 |
| 表 | 1 张，`need` 存**差值**（可为负） | 2 张，`need` 固定 + `window` 实际 |
| 触发 | 跨越 0 那条线 | `window[c]` 与 `need[c]` 相等／跌破 |
| 无关字符 | 自动往负走，**不用判断** | **必须** `need.count(c)` 挡 |

**formed 版两处保护不能省**：
1. `window[c] == need[c]` 不能写 `>=` —— 否则 `AABC` 的第三个 A 会重复 `formed++`
2. `need.count(c)` 不能省

**missing 版为何都不需要**：需求和实际存在同一个数里，无关字符从 0 一路往负走，永远 ≤ 0，两个判断天然不触发。
（《总结（十二）》2017 年那句"无论加减，出现次数都不可能大于 0"说的就是这个现象，但当时没说透原因是 `need` 存**差值**。）

**选择**：面试写 formed（每步能说人话，不易错）；missing **值得想通，不一定值得默写**。
formed 的"数种类"语感与 340／992 这类以种类数定义合法性的题相通。

### 卡片：297 序列化 —— # 的作用是标出子树边界

**唯一性从哪来**：单独的前／中／后序都无法唯一确定树（所以 105 要给两个）。
但**补上 `#` 之后，前序一个就够**——因为**前序的第一个元素永远是根**，读到它就能切出「接下来是左子树、然后右子树」，每棵子树读到哪结束由 `#` 显式告知。

中序不行：根埋在中间，不知道在哪切。后序可行（倒着读）。

> **`#` 的本质是把「子树在哪里结束」这个信息显式写进序列。**

**前序递归两大坑**：
1. 反序列化必须**共享同一个读取位置**（`istringstream&` 引用传递）；各层各持一份拷贝就全错。
2. `node->left = build(in);` 与 `node->right = build(in);` 必须是**两条独立语句** —— 写成一个表达式，C++ 求值顺序未定义，左右可能读反。

**前序 vs 层序**：代码 12 行 vs 25 行；输出长度都是 2N+1；
层序无递归（N=10^5 时前序会爆栈，但本题 N ≤ 10^4 够不着），且输出与 LeetCode 显示格式一致、好核对。

**易误判**：「层序是为了防爆栈」——理由真实但次要，且**避免递归不唯一指向 BFS**（前序可用显式栈改迭代）。
**结论**：面试默认前序递归。

### 卡片：42 接雨水 —— 按列算，核心是一个公式

```
water[i] = min(leftMax[i], rightMax[i]) - height[i]
```

`leftMax[i]` = `height[0..i]` 最大值，`rightMax[i]` = `height[i..n-1]` 最大值，**都含 i 自己**。

- **为何是 min**：木桶原理，水面由较矮那道墙决定。
- **为何非负**：两个 max 都包含 `height[i]` → `min >= height[i]`。**所以代码不需要判断"存不存得住水"**，直接减，存不住时恰好是 0。

全题化约为：**怎么快速拿到每个 i 的 leftMax / rightMax？**
暴力 O(N²) → 两遍预处理 O(N) 时间 O(N) 空间 → 对向双指针 O(N) 时间 **O(1) 空间**。

**双指针为何算矮的那根**：`LM` 已是 left 的**真实** leftMax；而 left 的真实 rightMax `>= height[right] > height[left]`，
所以 `min` 必落在 LM 这边，水量当场定死。高的那根内侧还没看，`min` 取哪边未定，算不出来。

### 卡片：11 vs 42 —— 同一个动作，保证的东西不同

两题都是对向双指针、都「移动矮的那根」、相等时都可移任意一侧。**但能否批量跳过不同：**

| | 11 | 42 |
|--|---|---|
| 移矮的保证了什么 | 它**已到顶**，最优搭档已算过 | 它**外侧信息已完整**，这一格水量可定死 |
| 答案由什么构成 | **一对** `(l,r)` 的面积 | **每一格**的水，逐格累加 |
| 相等时 `{l++; r--;}` | **可以** | **不可以** |

**反例 `[5,1,5]`**：一起移 → `left==right==1`，循环直接结束，中间那根从未被访问，4 格水丢失，答案算成 0。

> **11 在「排除候选」，跳过不影响；42 在「逐格累加」，跳过就是漏项。**

### 卡片：295 双堆 —— 三步法，不判断新元素该进哪边

**两条不变量**：① `size(small) == size(large)` 或多 1；② `small.top() <= large.top()`。

**addNum 固定三步（顺序不能换）**：
1. 无脑塞 `small`
2. `small` 堆顶让给 `large` —— **管性质②**（左边最大的已被扔到右边）
3. `large` 若反超，堆顶还回 `small` —— **只管性质①**（数量）

先调数量再调值就错了。这套写法把所有分支都省掉，不需要比较新元素该进哪个堆。

**两个坑**：`/ 2.0` 不能写 `/ 2`（int 截断）；C++ 最小堆直接用 `greater<int>`，
别用"push 负数"老技巧（`INT_MIN` 取负溢出）。

### 卡片：295 两个 follow-up —— 值域有界 / 分布有偏

**follow-up 1（全在 [0,100]）**：值域当下标，`cnt[101]`。
addNum O(1)，findMedian O(101)，**空间从 O(N) 降到 O(1)** —— 这一行才是质变。

**follow-up 2（99% 在 [0,100]）—— 题眼是先证明中位数仍在区间内**：
中位数落到区间外，需要 `lowCount >= total/2`，即**一半以上数据越界**，与 1% 前提矛盾。
**门槛其实是 50%，不是 99%**，条件远远富余。

于是越界值**根本不用存**，两个计数器即可。核心一行：`int run = lowCount;`
—— 越界的数不知道具体值，但**知道它在中位数的哪一边**；排名只需要"有多少个"，不需要"是多少"。

**面试要点**：说清假设比给代码更重要。这是基于分布假设的设计，讲不出假设它就是有 bug 的。

**通法**：
> 值域有界 → 用值域当下标，把「维护顺序」降级成「直接索引」。
> 分布有偏 → 热路径特化，冷路径用计数器／通用结构兜底。（缓存、慢查询回退、小对象内联同形）

### 卡片：480 滑动窗口中位数 —— 三个容器坑

**为何双堆失效**：堆只能看／弹堆顶，**不支持删除任意元素**；窗口右移要踢的那个数可能埋在堆中间。
→ 换成有序 + 可任意删除的结构：C++ `multiset`，Java `TreeSet`。

**坑一（C++）**：`multiset::erase(value)` 删**所有**相同值 → 必须 `erase(find(x))`。

**坑二（Java）**：`TreeSet` 不收重复元素 → 存 **index** 而非值。
**但光存 index 不够** —— 比较器必须用 index 做 tie-break：
```java
(a, b) -> nums[a] != nums[b] ? Integer.compare(nums[a], nums[b])
                             : Integer.compare(a, b);   // ← 解药
```
否则同值不同下标仍被判相等，照样被吞。附带好处：删除时手上有下标，`remove(i)` 精确删除。

> 坑一与坑二正好成对：**同是"容器怎么处理重复值"，C++ 删太多，Java 存不进**。

**坑三**：求中位数 **int 溢出** —— 本题范围 `[-2^31, 2^31-1]`，官方用例有 `[INT_MAX, INT_MAX]`。
必须 `((double)a + b) / 2`，不能 `(a + b) / 2.0`。295 遇不到，480 独有。

**单 multiset 写法**：`next(it, n)` 是 O(n)（双向迭代器），每次从 `begin()` 走会退化成 O(N·K)。
正解是**保存 `mid` 迭代器、每次只挪 ±1 步**；删到 `mid` 本身时要**先挪开再删**，否则迭代器失效。

### 卡片：224 计算器 —— 三变量 + 括号即一个数

**三变量**：`res`（本层已算出的）、`sign`（未参与计算的正负号）、`number`（未读完／未参与计算的数）。

于是跨层逻辑统一进同一套三变量模型，不需要额外规则；也解释了 `)` 为何在触发名单里——**带回一个数，有数就要结算**。

  `number` 此刻**必然为 0**（左括号前不可能紧跟数字），不用保存。然后 `res=0, sign=1`。
- **出层（`)`）**：本层结算 → 弹栈**恢复** `res`、`sign` → 把本层结果**赋给** `number` → 立即触发 res 更新。

**立即折叠只在 224 成立**（只有加减）。772 带乘除时，括号结果必须先停在 `number` 里，

### 卡片：BST 上的四个 bound —— 一个模板

> **从 root 一路下行，走「错」方向的那一步把当前结点记为候选；走到空为止，最后记下的候选就是答案。**

「走错方向」= 当前结点已满足条件，但可能还有更贴近 x 的，所以先存再找。

| 要找 | 名称 | 向右走的条件 | 记录时机 |
|---|---|---|---|
| 最小的 `> x` | upper_bound／后继（285） | `cur <= x` | 向左走时 |
| 最小的 `>= x` | lower_bound／ceiling | `cur < x` | 向左走时 |
| 最大的 `<= x` | floor | `cur <= x` | **向右走时** |
| 最大的 `< x` | 严格前驱 | `cur < x` | **向右走时** |

**两组对照**：
1. 前两行只差一个等号 —— 就是数组二分里那个「**等号归哪一边**」（见总结三）：归右跳过相等者（严格大于），归左留下它（大于等于）。
2. 前两行 vs 后两行**方向相反** —— 求「> x 的最小」在向左时记录（左边更小更贴近），求「< x 的最大」在向右时记录。

O(h)，不需要父指针，不需要递归。**记住那一句就能现推四个，不必分别背。**

### 骨架卡片：84 弹栈结算（用户 2026-09-21 自己的表述）

> **栈顶计算的时候，是按照栈顶高度作为最矮高度来考虑；左右边存的是第一个比它矮的下标，
> 因此下标之间的柱子都是比栈顶高的，从而这个高度横跨整段都成立。**

```
① 被弹的栈顶 = 矩形里最矮的那根，它的高 = 矩形的高

③ 两边界之间的柱子必然都更高 → 高度横跨整段成立
④ 宽 = 右 - 左 - 1（两堵墙够不着）
⑤ 面积 = h[top] * (i - left - 1)
```

**第 ③ 条是算法成立的理由**：「第一个比它矮」这个定义同时保证了
**边界是真的墙、中间是真的通**。

**易错**：连续弹多个时，每弹一次都要**重新读一次栈顶**（i=4 弹 3 再弹 2，左墙从 2 变成 1，宽从 1 变成 2）。

### 卡片：单调栈 —— 栈的方向与所求相反

**解决的问题**：为每个元素找左右两侧**最近的、第一个满足某大小关系**的元素。

| 要找 | 栈里维持 | 弹栈时机 |
|---|---|---|
| 最近的**更小** | **递增**栈 | 当前 < 栈顶 |
| 最近的**更大** | **递减**栈 | 当前 > 栈顶 |

> **记忆法：破坏单调性的那个元素，正是被弹出者要找的答案。**
> 想找「更小」，就得让「更小」成为破坏者，栈自然递增。

**弹栈那一刻两个边界一起到手**：当前元素 = 被弹出者的右边界；弹出后的新栈顶 = 它的左边界。这才是它省时间的地方。

1. **收尾** —— 扫完栈里还剩一批（右边界是 n）。最省事是**末尾追加高度 0 的哨兵**，循环自然清空栈；头部也可加 0 哨兵省掉「栈空时左边界 -1」的判断。同类边界见 224／227 的"扫到末尾要收尾"。

### 卡片：460 LFU —— 按频率分桶的 LRU

> **LFU = 按频率分桶的 LRU。每个桶内部就是一个小 LRU，`minFreq` 告诉你该动哪个桶。**

**四样东西**（第四样是个 int，但少了它淘汰做不到 O(1)）：
`keyToVal`（取值）、`keyToCnt`（知道在哪个桶）、`freqToKeys`（有序桶，取最旧）、**`minFreq`**（该淘汰哪桶）。

**核心动作只有一个：提频**。get 命中、put 命中都做一次。
```
touch(key): c = cnt[key]; cnt[key] = c+1
            从桶 c 删；若桶 c 空 且 minFreq==c → minFreq = c+1
            加到桶 c+1 末尾
```

**minFreq 只在两处变**：
1. 插入新元素 → `minFreq = 1`（**无条件**，新元素频率必为 1）
2. 提频后原桶空且原桶 == minFreq → `minFreq++`

**为何只 +1**：刚提频的那个 key 就落在 `minFreq+1` 桶里，该桶必非空。

**桶为何必须有序**：「频率相同淘汰最久未使用」= 桶内嵌了一个 LRU。
需要 O(1) 删任意 + O(1) 取最旧 → Java `LinkedHashSet`；C++ `list` 则额外需要 key→迭代器 表
（**那张表是容器选择带来的，不是算法需要的**）。

**与 146 对照**：LRU 只看时间（一条链，取尾部）；LFU 先看频率再看时间（一组桶，minFreq 定桶、取桶首）。


### 卡片：380 GetRandom O(1) —— 三条要求各逼出一个部件

```
要「等概率随机」   → O(1) 按下标访问 → 连续容器（vector / ArrayList）
要「O(1) 删任意」  → 连续容器中间删 O(n) → 「换到尾部再删尾部」
要「知道 val 在哪」→ hash: val -> 下标
```
**不是拼凑出来的结构，是被要求推出来的。**

**删除四步，顺序不能换**：
```
i = idx[val];  last = 尾元素
① arr[i] = last      ② idx[last] = i      ③ 删尾      ④ idx.erase(val)
```
**② 必须先于 ④** —— 要删的可能正好是最后一个（`last == val`）。先 erase 再 put 会把刚删的键加回去，
留下幽灵键，下次 insert 同一值误判「已存在」。

**换尾为何安全**：getRandom 只要等概率、**不要顺序**。
反过来说——**「无序」这个自由度正是被这个解法吃掉的**；若要求维持插入顺序，此技巧失效。

**同族手法**：heap 删堆顶也是「拿最后一个填坑」，目的相同——保持数组紧凑不留洞。

**Java 坑**：`list.remove(int)` 按下标 O(1)；`list.remove(Object)` 按值 O(n)。
`Integer i = map.get(v)` 要判 null，别直接赋 int（NPE）。

### 卡片：House Robber 系列 —— 两状态 DP，只换「邻居」

**统一骨架**（198／213／337 共用）。约束只有一条：**「选我」要求「邻居不选」**。
```
rob  = (邻居的 skip) + 当前值
skip = max(邻居的 rob, 邻居的 skip)
答案 = max(rob, skip)
```

| 题 | 邻居是谁 | 能否压缩 |
|---|---|---|
| **198** | 前一个位置 | ✅ 可压成一维 |
| **213** | 前一个 + 首尾成环 | 拆成**两次 198** |
| **337** | 左右孩子 | ❌ **不能压缩**，必须往上传两个值 |

**198 的一维公式就是两状态的压缩**：
```
skip[i] = max(rob[i-1], skip[i-1]) = dp[i-1]
rob[i]  = skip[i-1] + v            = dp[i-2] + v
→ dp[i] = max(dp[i-1], dp[i-2] + nums[i])
```
**这个代换只在一维成立**；树上父节点需同时知道两个孩子各自的 rob/skip，一个值传不上去。
所以 **337 的 g/h 不是新技巧，就是 198 两状态的树上版**。

**别用「必须偷第 i 个」那种定义**（原笔记的方法一）：转移变三项、答案要对所有 dp[i] 取 max、
还依赖「价值非负」。两状态一条都不占。

**213 的核心推理**（用户 2026-09-28：以前确实不知道）：
> **首尾不能同时选 ⟹ 任何合法方案必然「不选第一间」或「不选最后一间」（至少一条成立）。**
「两间都选」被禁 → 剩下只有：只选首 / 只选尾 / 都不选，**三者都满足「至少有一间没选」**。
→ 跑两次 198（去掉首 / 去掉尾）取 max。
**严格证明要走两个方向**：
- **不漏**：S 合法 ⟹ `0∉S` 或 `n-1∉S`。前者 ⟹ S 是 `nums[1..n-1]` 上的合法线性方案 ⟹ 该支 ≥ value(S)。对称。⟹ **max ≥ 最优**
- **不多**：T 由 `robLinear(1,n-1)` 得出 ⟹ `0∉T` ⟹ 环形那条「首尾不同选」**自动满足** ⟹ T 环形合法 ⟹ 该支 ≤ 最优。对称。⟹ **max ≤ 最优**
两方向夹出等号。

**「若最优解既不选首也不选尾」怎么办** —— 被两支**同时**算到，但无害，理由正是那两个不等式：
```
两支各自 ≤ 最优（不多）；两支 max ≥ 最优（不漏）
→ 重复计算不可能把结果推到最优值之上
```
**max 对重复免疫** —— 这就是「覆盖足够」的全部含义。
**A、B 有重叠不影响正确性** —— 取 max，同一方案算两遍无副作用。**要的是「覆盖」不是「划分」。**
**「不选首」≠「必选尾」**：情况 A 在 nums[1..n-1] 上自由决定，允许尾也不选，故「都不选」已被涵盖。
**小 n 验证**（怀疑通常出在这里）：
| n | 实际 | 公式 | |
|---|---|---|---|
| **1** | `nums[0]` | `max(0,0)=0` | ❌ **必须特判** |
| 2 | 只能选一个 | `max(n0,n1)` | ✅ |
| 3 | 两两相邻，只能选一个 | 三者最大 | ✅ |
**只有 n == 1 要特判**，n ≥ 2 公式本身就对。

**337 为何「只用一个 f」那种写法需要 memo**：拿不到 h(L)，只能把它**展开成孙子的 f**，
于是 f(L.left) 在算 f(L) 时被重复计算 → 必须 memo。两状态版把 h 直接传上去，一遍 DFS 即可。

**337 为何不能压缩成一个值**（反例）：
```
root=1 → L=100 → 孩子 3, 4
g(L)=100, h(L)=7, f(L)=max(100,7)=100
g(root) 正确 = 1 + h(L) = 8；若只有 f(L) → 1+100=101，root 与 L 同时被选，非法
```
**f(L) 含着 L 自己，而我们要的恰是「不含 L」的值，从 f(L) 反推不出 h(L)。**
反过来只传 h 也不行（算 h(parent) 需要 g(L)）。**两个值缺一不可。**


### 卡片：DP 状态定义的两个轴（粒度部分由用户 2026-09-28 提出）

状态定义要同时定下**方向**和**粒度**，两个轴都定了才算定完。

**轴一：方向**（以 i 结尾 / 以 i 起头）
> 判据：**当「当前决策是否合法／有多好」取决于后面还没走的部分时，必须从后往前定义。**
> 最纯例证 174 Dungeon Game（血量 ≥ 1 是未来的约束）。

**轴二：粒度**（一个位置维护几个量）—— 用户原话的三分法：

| | 维护什么 | 答案在哪 | 代表题 |
|---|---|---|---|
| **①** 只有「必须以 i 结尾」 | 一个**受约束**量 | **遍历取 max** | 53 方法三、300、674、152 |
| **②** 「前 i 个最优」+「必须以 i 结尾」 | 自由量 + 受约束量 | **直接读末项** | 53 方法二 f／g |

> 压缩判据：**「不选前一个」是否恰好等于「问题缩小一格」**。链上成立，树上不成立。

**③ 的真名是「状态机 DP」**，阶段可多于两个：
198/337 选·不选（2）｜121/122 持有·不持有（2）｜**309 含冷冻期（3）**｜**123/188 买卖 k 次（2k）**。
遇到「额外限制导致不能随便转移」（冷冻期、手续费、次数上限）→ 先想能不能画成状态机。

### 方法论卡片：求 max／min 只需「覆盖」，不需「划分」（2026-09-28 从 213 提炼）

> **求最优值的问题，把解空间拆成若干情况时，只要求「并集覆盖全部合法方案」，
> 不要求「不重不漏」。同一个方案被算两遍，对 max／min 没有任何副作用。**

**213 就卡在这里**：把环拆成「去掉首」和「去掉尾」两段，两段**有重叠**
（`{1,2,3,4,5}` → `{2,3,4,5}` 和 `{1,2,3,4}`，都含 `{2,3,4}`）。
很多人下意识想做"不重不漏的划分"，然后发现分不干净就卡住了。**根本不需要划分。**

**但这条只对「求最优值」成立。**按"要什么"分三档，正好和 kSum 家族那套对上：

| 要什么 | 重复的后果 | 必须做什么 |
|---|---|---|
| **max／min** | **无害**（取极值，算两遍一样） | 只需**覆盖** ← 213 |
| **计数（方案数）** | **致命**（直接多算） | 必须**不重不漏** ← 923、518、377 |
| **列出具体内容** | 结果里出现重复项 | 必须**去重** ← 15 的三处去重 |

所以「15 要去重、923 要数清楚、213 可以重叠」不是三种记忆，是**同一条判据的三个分支**：
**先问「我要的是极值、数量、还是内容」。**

**自检**：当你开始纠结"这两种情况会不会算重"时，先回头看要求的是什么。
若是 max／min，这个纠结本身就是多余的。

### 卡片：股票系列 —— 一台状态机的六种改装

**基础（就是 122）**。每状态记「处于该状态时口袋里最多有多少钱」：
```java
int prevHold = hold, prevCash = cash;               // ★ 先存旧值
hold = Math.max(prevHold, prevCash - price);        // 持有 / 今天买
cash = Math.max(prevCash, prevHold + price);        // 空仓 / 今天卖
// 初始 hold=-prices[0], cash=0；答案 = cash
```

**写法约定**：**开头存 prev，右边只读 prev，左边写回原变量。** 左边的变量本身就是 cur，不必另起名。

| 题 | 限制 | 怎么改 | 方向 | 状态数 |
|---|---|---|---|---|
| **122** | 无 | 基础形式 | — | 2 |
| **121** | 至多 1 次 | 买入源 `prevCash` → **`0`** | **A 改式子** | 2 |
| **714** | 每笔 fee | 卖出 `+price` → **`+price-fee`** | **A** | 2 |
| **309** | 卖后冷冻 1 天 | `cash` **拆成** `sold`/`rest`，买只能来自 `rest` | **B 加状态** | **3** |
| **123** | 至多 2 次 | 按次数**分层**，`0→h1→c1→h2→c2` | **B** | **4** |

**123 四状态的语义**（读懂转移式的前提）：
- `hold1` 手上握第一笔 → **恒为负**（= `-最低价`，买入前口袋必须是 0）
- `cash1` 第一笔已卖完 → ≥ 0
- **`hold2`** 第一笔已完成、手上握第二笔 → **可正可负** = 第一笔利润 − 第二笔买入价
- `cash2` 两笔都卖完 → 答案

**`hold2` 能为正、`hold1` 不能** —— 这是「分层」最直观的标记。

**「第一笔已完成」谁保证的？入口保证的。** `hold2` 唯一外部来源是 `prevCash1 - price`，
而 `cash1` 就意味着第一笔已卖完 → **历史被编码在状态名里**（下标 2 = 这是第二笔），转移式不必再检查。
`0→hold1→cash1→hold2→cash2` 是**单向链**，要到 `cash2` 必须一路走完，赖不掉。

**具体化 `prevHold2`**（`prices=[3,3,5,0,0,3,1,4]`，答案 6）：
第 3 天 `hold2 = prevCash1 − 0 = 2` —— **口袋 2 块（第一笔赚的）+ 手上一支成本 0 的股票**；
第 7 天 `prevHold2 + 4 = 6` ✓ 对应真实操作 `(5−3) + (4−0) = 6`。
| **188** | 至多 k 次 | 同上，j=1..k（123 是 k=2 展开） | **B** | **2k** |

> **判据：当「能不能做某动作」取决于「历史」而非「当前状态」时，必须加状态。**
> 714 扣费只看当前动作 → 不加；309 看「昨天是否刚卖」→ 拆 cash；123/188 看「已交易几次」→ 分层。

**121 的 hold 就是 `-最低价`**：`max(hold,-price)` = `-min(price)` ⟹ `cash = max(cash, price-minSoFar)`
—— **状态机和「维护历史最小值」是同一件事的两种写法**。
**诊断法**：121 的 hold **恒 ≤ 0**；hold 一旦变正 = 口袋里有赚来的钱 = 已完成过交易 = 式子写错了。

### 卡片：滚动数组何时不能就地更新（2026-09-28，用户主张 prev/cur）

> **判据不是「有没有被覆盖」，而是「覆盖多算进去的那一项对应什么动作」。**
> 该动作**净收益 ≤ 0 或本来合法** → 无害；**本身违规** → 真 bug。

| 题 | 多算进的项 | 含义 | 结果 |
|---|---|---|---|
| 122 | `cash[i-1]` | 当天买当天卖，净 0 | 无害 |
| 121 | `0` | 同上 | 无害 |
| 714 | `cash[i-1]-fee` | 当天买卖还交费，净亏 | 无害（更差）|
| 123/188 | `cash[j-1]` | 只做 j−1 笔、第 j 笔跳过 | 无害（合法）|
| **309** | `rest` 吃到当天的 `sold` | **跳过冷冻期** | ❌ **真 bug** |

**309 反例** `[1,2,3,0,2]`：正解 **3**，就地更新算出 **4**
（非法排程：第 2 天卖价 3、第 3 天买价 0，中间没隔天）。

**通用原则**：**状态数 ≥ 3、或转移间有依赖顺序 → 一律先存 prev，不要就地滚。**
就地滚只在「一眼看出多算项无害」时才值得（如两状态的 122）。
**这和背包降维选正序/倒序是同一类判断**：都在问「用新值会让哪条非法路径变得可达」。


### 卡片：312 戳气球 —— 「一段 + 两堵墙」＋「k 最后戳破」

**不变量**（两条缺一不可）：
```
dp[i][j] = 把 i..j 之间气球全部戳破的最大金币，
           且以 nums[i-1] 与 nums[j+1] 作为左右两道【不会被戳破的墙】
```
1. **区间外的 i-1 / j+1 是墙** —— 子问题不是「孤立一段」，而是「一段 + 两堵墙」
2. **枚举的 k 是「最后一个被戳破的」**，不是第一个

**为什么必须是「最后」**：若 k 第一个戳，左右两段的边界会被对方段的气球影响，
`dp[i][k-1]` 的右墙可能是 `nums[k+1]..nums[j]` 中任意一个 → **子问题无法独立**。
反过来 k 最后戳，其余全已消失，k 紧贴两墙 → 得分固定，左右两段互不影响。

**转移**：
```
dp[i][j] = max over k in [i,j] of  dp[i][k-1] + nums[i-1]*nums[k]*nums[j+1] + dp[k+1][j]
```
⚠️ **中间那项最易写成 `nums[k-1]*nums[k]*nums[k+1]`**（照搬题面），那是「第一个戳 k」的算法，错。
三个下标是 **i-1、k、j+1**。

**基本情况** `dp[x][x] = nums[x-1]*nums[x]*nums[x+1]` —— 恰好与题面同形，
是因为 `i-1=x-1, j+1=x+1` 的**巧合**，别据此推广。

**编码**：三重循环下标难写，优先 **dfs + memo**；若用迭代则按**区间长度从小到大**扩。


### 卡片：403 青蛙过河 —— 状态必须带上「上一跳长度」

**不变量**：
```
f(i, j) = 能否站在位置 i，且【最后一跳的长度恰好是 j】
```
**为什么必须带 j**：下一跳能跳多远完全取决于上一跳 —— 「能不能做某动作取决于历史」，
那段历史必须编码进状态。（同 309 冷冻期、123/188 交易次数）

**逆向转移**（i 是怎么被跳到的）：
```
f(i, j) = f(i-j, j-1) || f(i-j, j) || f(i-j, j+1)
```
> **三项的第一个下标都是 `i-j`！** 这一跳长 j ⟹ 上一落脚点**恒为 i-j**，变的只有上一跳长度 p ∈ {j-1, j, j+1}。

❌ 易错写成 `f(i-j-1, j+1)`：那表示在 `i-j-1` 落地、上一跳 j+1，从那里跳 j 只到 `i-1`；
要到 i 得跳 j+1，算出来的是 `f(i, j+1)` 而非 `f(i, j)`。

**初始** `f(0,0) = true`（未跳过，视作上一跳长 0，故第一跳只能是 1）。
**答案**：`f(最后一块石头, j)` 是否存在某个 j 为 true。

**实现推荐正向 push**：坐标稀疏，逆向要反查「i-j 是不是石头」；
正向从已知可达的石头往外推 `(s,k) → (s+k-1,k-1), (s+k,k), (s+k+1,k+1)`，天然跳过不存在的位置。
Java 用 `Map<Integer, Set<Integer>>`（同一个 (s,k) 可由多路到达，用 Set 去重）。


### 卡片：689 三段不重叠子数组 —— 枚举中间段，左右取预处理最优

**思路**：三段不重叠 ⟹ 固定中间段起点 `m` 后，左段起点 ≤ `m-k`、右段起点 ≥ `m+k`。
所以预处理「左边范围内最优」「右边范围内最优」，枚举 m 即可 O(1) 拼接。

**不变量**（两个数组存的都是**起点**，不是终点）：
```
sum[i]   = nums[i..i+k-1] 之和                i ∈ [0, n-k]
left[i]  = 在 [0, i]   内，和最大的窗口【起点】
right[i] = 在 [i, n-k] 内，和最大的窗口【起点】
```

**⚠️ 两个不等号方向相反 —— 这就是「字典序最小」落地的地方**：
| | 不等号 | 理由 |
|---|---|---|
| `left`（正向扫） | **`>`** | 平手**保留旧的**（旧下标更小）|
| `right`（反向扫） | **`>=`** | 平手**取当前的**（当前下标更小）|

方向相反、**目标一致：都让留下的下标尽可能小**。

**拼接**：`for m in [k, n-2k]`，`total = sum[left[m-k]] + sum[m] + sum[right[m+k]]`，用 `>` 更新。

❌ **易错**：写成 `left[m-1]` —— 左段 `[s,s+k-1]` 要在中段左边须 `s ≤ m-k`，用 `m-1` 会**重叠**。
❌ **易漏**：题目要**返回下标**（非和）、**多解取字典序最小**。

**验证** `nums=[1,2,1,2,6,7,5,1], k=2` → `sum=[3,3,3,8,13,12,6]` → m=3 时 3+8+12=23 → `[0,3,5]`。


### 卡片：673 最长递增子序列的条数 —— 两个数组，覆盖时抄 cnt[j]

**不变量**（缺一个都写不出）：
```
len[i] = 以 nums[i] 结尾的 LIS 的【长度】
cnt[i] = 以 nums[i] 结尾、长度恰为 len[i] 的 LIS 的【条数】
初始 len[i] = cnt[i] = 1
```

**转移**（对每个 i，遍历 j < i 且 `nums[j] < nums[i]`）：
```java
if (len[j] + 1 > len[i])  { len[i] = len[j] + 1; cnt[i] = cnt[j]; }   // 更长 → 覆盖
else if (len[j] + 1 == len[i]) { cnt[i] += cnt[j]; }                   // 并列 → 累加
// 更短 → 跳过
```

**答案** = 所有 `len[i] == maxLen` 的 `cnt[i]` **之和**（最长 LIS 可有不同结尾，如 `1,2,3,9,8,7`）。

**★ 最易错：覆盖时是 `cnt[i] = cnt[j]`，不是 `cnt[i] = 1`。**
理由：「以 i 结尾、长度 `len[j]+1`」的条数 = 「以 j 结尾、长度 `len[j]`」的条数
—— 那每一条后面都能接上 `nums[i]`。
**反例 `[1,3,2,4,5]`**：`cnt[3]=2`（`[1,3,4]`/`[1,2,4]`），`cnt[4]=cnt[3]=2` → 正解 **2**；
若写 `cnt[i]=1` 则得 1。

**两个分支必须分开**（一个覆盖、一个累加），合成一个 `if` 必错。
**`[2,2,2,2]` → 5**：严格递增，相等接不上，全保持初值 1 —— 这就是初始化为 1 的意义。
复杂度 O(n²)。


### 卡片：486 博弈 DP —— 三种思路，难点都在「先手翻转」

**根本难点**：`dp[i][j]` 是「站在 [i,j] 这个局面上的先手」的分。我取走 `nums[i]` 后，
`[i+1,j]` 的先手变成**对手** → `dp[i+1][j]` 是对手的分，不是我的。
（直觉公式 `max(dp[i+1][j]+nums[i], …)` 错就错在这里。）
我要的是 `sum(i+1..j) − dp[i+1][j]`，围绕怎么拿到它有三条路：

| | 不变量 | 转移 | 子状态 | 判胜 |
|---|---|---|---|---|
| **A（用户采用）** | 先手**总分** | `max{ min(dp[i+2][j], dp[i+1][j-1]) + nums[i], min(dp[i+1][j-1], dp[i][j-2]) + nums[j] }` | 3 | `2·dp ≥ sum` |
| B | 先手总分 | `max( nums[i] + sum(i+1..j) − dp[i+1][j], … )` | 2 + 前缀和 | `2·dp ≥ sum` |
| C | 先手**净胜分** | `max( nums[i] − dp[i+1][j], nums[j] − dp[i][j-1] )` | 2 | `dp ≥ 0` |

- **A**：跨过对手那一层，**max 套 min**（外层我选、内层对手选），博弈两层结构最直观
- **B**：把 A 的「跨层取 min」换成「总和减对手最优」——对手的最优已替我考虑了「他会让我少拿」
- **C**：净胜分**反对称**（换人只变号），「先手翻转」被压成一个负号

⚠️ **平局算先手赢** → 判胜是 `>=`，不是 `>`（原笔记写成「大于总和一半」，已修）。

**用户 2026-10-02 决定**：目前不采用 C，保留 A 为主。
**待验证**：遇到 877／1140／1406 等其他博弈题时，再比较哪种视角更顺手。


### 卡片：375 猜数 —— 我能控制的取 min，我控制不了的取 max

**用户原话（2026-10）**：
> 猜 x 之后还是继续在 [i,x-1] 和 [x+1,j] 其中之一里猜，**但这是自己不能控制的**，
> 最坏情况下对手把数藏在**代价较大**的一侧；**而怎么选 x 是自己可以主动掌握的**，所以选最有利的。

⚠️ 「代价较大」= **dp 值较大**，**不是数值较大**。n=4 猜 3：左 [1,2] 还要 1、右 [4] 还要 0 → 对手选**左边**。

```
dp[i][j] = 已知答案落在 [i,j] 内时，保证猜中的最少钱
dp[i][j] = min over x ( x + max(dp[i][x-1], dp[x+1][j]) )
             ↑我挑 x            ↑对手挑边
```

**题意怎么懂**：带现金出门——不问平均花多少，问「带多少保证够」→ 按最倒霉算；但路线我可选 → 挑最倒霉时最便宜的。
把答案想成**故意坑你的人**，每次都挑让你更花钱的回答。

**识别信号**：① 求最优值 ② 猜完剩一个更小区间（同构）③ **二分不行**（n=4 猜中点 2 要 5、猜 3 只要 4）→ 区间 DP。
二分失效的本质：**每次猜的代价取决于猜哪个数** → 「等权则贪心，带权则 DP」又一例。

**决策树视角**：代价 = 树里**最重路径**的权重和。二分每节点权重 1（按数量平衡，根在中点）；
本题权重 = 猜的数（按权重平衡）→ **贵的那边要浅，便宜的那边可以深**，根偏右。

**两个顺序相反**：计算自底向上，决策自顶向下 —— **根是最先猜的，却是最后算出来的。**
与 312 对照：375 挑「最先猜的」、312 挑「最后戳的」，时间相反但角色相同——**把区间切成独立两半的那个点**。

**不变量是「系统发的牌」**（用户 2026-10 语）：「答案一定在 [i,j]」不是推出来的，
是每次「高了/低了」的回答替你维护的。
> **对手能坑你，但不能骗你。** 坑 = 挑更贵的一边（允许，即 max）；骗 = 前后矛盾（不允许）。
> 不变量靠的正是「不能骗」。若允许撒谎（带谎言的二十问），区间不变量失效、区间 DP 塌掉。

**和二分查找是同一张牌**：都是「答案恒在当前区间内」，只是发牌的人不同——
二分靠**数组有序**，375 靠**对手回答前后一致**。

**minimax 的边界**（用户感悟：「选对手留给自己烂摊子里最好的」）：
对面是**对手**（会钻空子）→ 按最坏准备；对面只是**运气**（随机）→ 按最坏会过度保守，该用期望值。
本题若改成「平均花多少」，只把内层 max 换成概率加权平均，结构不变。


### 卡片：378 有序矩阵第 k 小 —— 三种方法 = 用掉多少「局部有序」

**题眼**：行有序、列有序 **≠ 整体有序**（按行拼起来不是有序的），所以不能直接下标定位。

| | 利用了什么 | 时间 | 空间 |
|---|---|---|---|
| quickselect | 什么都没用 | 平均 O(n²) | O(n²) |
| 堆（= 23 多路归并）| **只用行有序** | O(k log min(n,k)) | O(min(n,k)) |
| 值域二分 | **行列都用** | O(n log X) ≈ O(32n) | O(1) |

**值域二分不变量**：`答案 = 第一个使 count(<= M) >= k 的 M` —— 就是「**单调谓词第一个 true**」（9/18）。
❌ **不能写「恰有 k 个」**：`[[1,2],[1,3]], k=1` 不存在恰好 1 个的 M。原笔记把它当特例补丁，实为不变量错。
**为何答案必在矩阵里**：若 M 不在，`count(<=M) = count(<=M-1)` → M-1 也满足，与最小矛盾。
**O(n) 计数**：从左下角，`<= M` 则 `count += r+1` 右移，否则上移。
> **用户的总结：每一步都整条地处理掉一列或一行——满足的一侧一次性计数，不满足的一侧一次性丢弃，然后前进。**
- `<= M` → 列递增 → 以上整列都满足 → **计入 r+1**，右移
- `> M` → 行递增 → 往右整行都不满足 → **丢弃**，上移
- 必须从左下/右上出发：两个方向一增一减，比较一次才能确定处理哪条

**与排序双指针同构**：240、378 的 count、167 Two Sum II（`nums[i]+nums[j]` 的隐式表，见总结二十二第一节）
都是「**两向单调的二维表 + 从一增一减的角出发 → 每步整条排除 → O(n²) 格子 O(n) 步**」。
**堆可只放前 min(n,k) 行**：第 r 行开头至少是第 r+1 小。
**选择**：k 小 → 堆；k 大 → 值域二分。

| 树同层中的远近 | 编号 i | 左 2i / 右 2i+1 | 662 |

**诊断**：用户 2017 年笔记全是 C++，近来改写 Java。这几天卡住的每一处，**恰好都是 C++ 与 Java 行为不同的地方** —— 不是 Java 整体差，是**用 C++ 的直觉写 Java**。

| # | 坑 | C++ | Java |
|---|---|---|---|
| ① | **基本类型 vs 包装类型** | `vector<int>` 就是 int | `List<Integer>` 是包装类型，int↔Integer 处处要转 |

**① 的各种表现**（全是同一个概念）：
- `list.toArray(new int[n])` **编译不过** → `list.stream().mapToInt(Integer::intValue).toArray()`，或一开始就开 `int[]`

- `list.remove(int)` 按下标 vs `list.remove(Object)` 按值
- `int i = map.get(k)` 不存在时 **NPE**（拆箱 null）

先把 ArrayList 填满 ／ 用真数组 `List<Integer>[] g = new List[n]` 判 null ／ 用 `HashMap.computeIfAbsent`。
**唯独不能对没填满的 ArrayList 判 null。**

### 卡片：451 Java（方法三，推荐）+ 桶写法（2026-10-06）

```java
// 方法三：计数 + 只给不同字符排序，O(n + σlogσ)，额外空间 O(σ)
public String frequencySort(String s) {
    int[] cnt = new int[128];
    for (char c : s.toCharArray()) cnt[c]++;
    List<Character> chars = new ArrayList<>();
    for (char c = 0; c < 128; c++) if (cnt[c] > 0) chars.add(c);
    chars.sort((a, b) -> Integer.compare(cnt[b], cnt[a]));
    StringBuilder sb = new StringBuilder();
    for (char c : chars)
        for (int k = 0; k < cnt[c]; k++) sb.append(c);
    return sb.toString();
}
```

```java
// 方法二：桶，bucket[f] = 恰好出现 f 次的字符
List<Character>[] bucket = new List[s.length() + 1];   // 泛型数组只能这样建；每格初始 null
for (char c = 0; c < 128; c++) {
    if (cnt[c] == 0) continue;
    if (bucket[cnt[c]] == null) bucket[cnt[c]] = new ArrayList<>();
    bucket[cnt[c]].add(c);
}
for (int f = s.length(); f >= 1; f--)                    // 高频到低频，不用翻转
    if (bucket[f] != null)
        for (char c : bucket[f])
            for (int k = 0; k < f; k++) sb.append(c);     // ← 用户写成了 i++，死循环
```

**用户的两个 bug**：`int cnt = new int[128]`（少 `[]`）；内层循环自增写成外层变量 `i++`。**习惯**：写完内层循环，对一遍 for 头三段是不是同一个变量。

**方法二 vs 三**：时间都 O(n)；三省掉长度 n+1 的桶（额外空间 O(σ) vs O(n)），更重要的是好写、不碰泛型数组和 null。

**128／256**：ASCII 0–127 → `int[128]`；只有小写 → `int[26]` + `c-'a'`；扩展 ASCII／说不清 → `int[256]`；Unicode → HashMap。数组开多大看**题目约束**。
